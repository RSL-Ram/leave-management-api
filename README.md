# Leave Management API

A Spring Boot REST API that lets employees submit and manage leave requests for an organization's HR system.
Data is kept in an in-memory store (`ConcurrentHashMap`), so no database is needed.

## Project Overview

| Item        | Details                                   |
|-------------|-------------------------------------------|
| Language    | Java 17                                   |
| Framework   | Spring Boot 3.3.5 (Web, Validation, Test) |
| Build tool  | Maven                                     |
| Storage     | In-memory `ConcurrentHashMap` repository  |
| Profiles    | `dev` (default), `prod`                   |

### Architecture

The code follows a layered design: **Controller → Service → Repository**. Every dependency is injected through the constructor.

```
src/main/java/com/rsl/leavemanagement
├── LeaveManagementApplication.java
├── controller   LeaveController                  – REST endpoints under /leaves
├── service      LeaveService, LeaveServiceImpl   – business rules
├── repository   LeaveRepository, InMemoryLeaveRepository – thread-safe ConcurrentHashMap store
├── model        LeaveRequest, LeaveType, LeaveStatus
├── dto          LeaveRequestDto, LeaveResponseDto, ErrorResponse
├── exception    LeaveNotFoundException, InvalidLeaveRequestException, GlobalExceptionHandler
└── config       LeaveProperties (@ConfigurationProperties), SampleDataConfig (dev-only seed data)
```

### Leave Request Model

| Field        | Type        | Notes                                                                 |
|--------------|-------------|-----------------------------------------------------------------------|
| `id`         | Long        | Generated by the server                                               |
| `employeeId` | String      | Required, 3–20 characters: letters, digits or `-`                     |
| `leaveType`  | Enum        | `CASUAL`, `SICK`, `EARNED`, `MATERNITY`, `PATERNITY`, `UNPAID`        |
| `startDate`  | Date        | Required, `yyyy-MM-dd`                                                |
| `endDate`    | Date        | Required, `yyyy-MM-dd`, on or after `startDate`                       |
| `reason`     | String      | Required, at most 500 characters                                      |
| `status`     | Enum        | `PENDING`, `APPROVED`, `REJECTED`, `CANCELLED`                        |

### Business Rules

- A new request always starts as `PENDING`. Any `status` sent on create is ignored.
- On update, `status` is optional. If it is left out, the current status stays as it is.
- `endDate` must be on or after `startDate`.
- One request cannot be longer than `leave.max-days-per-request` days. This value is configurable for each profile.

### Configuration and Profiles

Configuration lives in `src/main/resources`:

| File                    | Purpose                                                           |
|-------------------------|-------------------------------------------------------------------|
| `application.yml`       | Common settings. Sets `dev` as the default profile                |
| `application-dev.yml`   | Port 8080, max 45 days per request, DEBUG logging, loads sample data |
| `application-prod.yml`  | Port 8081, max 30 days per request, quieter logging, no sample data  |

Custom properties (`leave.*`) are bound to the `LeaveProperties` record, which is validated when the app starts.

## Build and Run

**Prerequisites:** JDK 17 or newer and Maven 3.9 or newer.

```bash
# Build and run all tests
mvn clean package

# Run with the default (dev) profile on http://localhost:8080
mvn spring-boot:run

# Run with an explicit profile
mvn spring-boot:run -Dspring-boot.run.profiles=prod

# Or run the packaged jar
java -jar target/leave-management-api-0.0.1-SNAPSHOT.jar
java -jar target/leave-management-api-0.0.1-SNAPSHOT.jar --spring.profiles.active=prod
```

In the `dev` profile, three sample leave requests are loaded at startup so the API can be tried out right away.

## API Endpoints

Base URL: `http://localhost:8080`

| Method | Endpoint        | Description                     | Success response  | Error responses |
|--------|-----------------|---------------------------------|-------------------|-----------------|
| GET    | `/leaves`       | Retrieve all leave requests     | `200 OK`          | –               |
| GET    | `/leaves/{id}`  | Retrieve a leave request by ID  | `200 OK`          | `400`, `404`    |
| POST   | `/leaves`       | Create a new leave request      | `201 Created` + `Location` header | `400` |
| PUT    | `/leaves/{id}`  | Update an existing leave request| `200 OK`          | `400`, `404`    |
| DELETE | `/leaves/{id}`  | Delete a leave request          | `204 No Content`  | `404`           |

### Example Requests

```bash
# Create
curl -i -X POST http://localhost:8080/leaves \
  -H "Content-Type: application/json" \
  -d '{"employeeId":"EMP-100","leaveType":"SICK","startDate":"2026-10-12","endDate":"2026-10-13","reason":"Flu"}'

# Get all
curl http://localhost:8080/leaves

# Get by id
curl http://localhost:8080/leaves/4

# Update (status is optional)
curl -X PUT http://localhost:8080/leaves/4 \
  -H "Content-Type: application/json" \
  -d '{"employeeId":"EMP-100","leaveType":"SICK","startDate":"2026-10-12","endDate":"2026-10-14","reason":"Flu - extended","status":"APPROVED"}'

# Delete
curl -i -X DELETE http://localhost:8080/leaves/4
```

A ready-to-run collection is also available in [`requests.http`](requests.http). It works with the IntelliJ HTTP Client and the VS Code REST Client.

### Error Format

`@RestControllerAdvice` (`GlobalExceptionHandler`) handles every error and returns the same JSON structure:

```json
{
  "timestamp": "2026-09-29T16:19:31.787",
  "status": 400,
  "error": "Bad Request",
  "message": "Validation failed",
  "path": "/leaves",
  "fieldErrors": {
    "employeeId": "employeeId is required",
    "reason": "reason is required"
  }
}
```

| Situation                                        | Status |
|--------------------------------------------------|--------|
| Bean Validation failure (`@Valid`)                | 400    |
| Business rule violation (date range, max days)    | 400    |
| Malformed JSON, unknown enum value or bad date    | 400    |
| Non-numeric `{id}`                                | 400    |
| Leave request not found                           | 404    |
| Unsupported HTTP method                           | 405    |
| Any other unexpected error                        | 500    |

## Testing

```bash
# Run the whole test suite
mvn test

# Run a single test class
mvn test -Dtest=LeaveServiceImplTest
mvn test -Dtest=LeaveControllerTest
```

| Test class                        | Type                         | Scope                                                     |
|-----------------------------------|------------------------------|-----------------------------------------------------------|
| `LeaveServiceImplTest`            | Unit test (JUnit 5 + Mockito)| Service logic, business rules and not-found handling       |
| `LeaveControllerTest`             | `@WebMvcTest` + MockMvc      | HTTP status codes, JSON payloads, validation and error handling |
| `InMemoryLeaveRepositoryTest`     | Unit test                    | ID generation, save, update and delete in the store       |
| `LeaveManagementApplicationTests` | `@SpringBootTest`            | Context loads with the `dev` profile and binds its properties |

Surefire reports are written to `target/surefire-reports/`.
